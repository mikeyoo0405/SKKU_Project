## 0. 이번 우선 구현: 2026-11-24 교수님 시연

### 목표와 작업 순서

기존 수집 → 후보 선정 → 감정 제안 → 사람 검수·수동 추가 → 확정 저장 흐름에 장면 전환 경고와 측정값 요약을 더한다. 교수님께 장면 전환을 검수에 참고하고, 처리 병목과 사람이 확정한 결과를 확인할 수 있음을 보여준다. 이번 문서 갱신은 구현 완료를 의미하지 않는다.

**기존 동작 점검 → S1 장면 전환 경고 → S2 처리 시간 요약 → S3 검수 현황 요약 → 실제 영상 확인·녹화** 순서로 진행한다. 아래 시연 범위는 후속 B~E의 전체 구현을 선행 조건으로 요구하지 않는다.

### S1. 장면 전환 경고

- PySceneDetect의 `AdaptiveDetector`를 우선 사용한다. 별도 신경망 가중치나 새 감정 모델을 추가하지 않는다. 선택 의존성과 늦은 import로 기존 앱 실행을 유지한다.
- 모드는 `off` / `warn`만 구현한다. 원본의 장면 전환 시각을 후보 경계와 대조해 경고를 표시한다. 컷이 있다는 이유로 화자 전환이나 발화 잘림으로 단정하지 않는다.
- 감지 결과는 원본 지문·분석기 버전·설정과 함께 캐시한다. 기존 완료 후보도 ASR·VAD·감정 재추론 없이 장면 분석을 보완할 수 있게 한다. 기존 후보 캐시가 있다는 이유로 신규 분석을 건너뛰지 않는다.
- 수동 추가·경계 수정 후에는 현재 구간 기준으로 경고를 다시 계산한다. 원본이 바뀌면 과거 장면 결과를 사용하지 않는다.
- 미설치·실패·미분석을 전환 없음과 구분하고 수동 검수를 계속 허용한다. 첫 도입은 컷 감지이며 페이드 전용 감지는 후속 범위다.
- 변경 예정: 신규 `app/scene.py`, `test_scene.py`; `app/config.py`, `tools/run_batch.py`, `app/review.py` 또는 조회 전용 조합 로직, `static/review.mjs`, `static/app.js`, `static/index.html`, `static/style.css`, `pyproject.toml` 및 필요한 잠금 파일·설정 예시·설치 안내.

### S2. 처리 시간 요약

- 기존 배치 측정 경로를 확장해 실행 식별자·측정 시각과 이번 실행의 전체/단계 시간을 구분해 저장한다. 전체 배치 wall time과 영상별 시간을 명시하고 병렬 단계 시간 합계를 전체 시간으로 표시하지 않는다.
- 다운로드·오디오·VAD·ASR·장면 분석·후보 추출 중 실제 실행한 단계만 이번 실행 값으로 기록한다. 재사용 단계는 캐시 사용으로 표시한다. 측정되지 않은 값은 `null`과 미측정 표시를 사용한다.
- 기존 모델 실행에 추론 시간이 있으면 별도 실행의 값으로 표시한다. 수집 배치와 별도 실행된 감정 추론 시간을 묵시적으로 합쳐 전체 처리 시간으로 만들지 않는다.
- 화면은 마지막으로 기록된 실행의 요약부터 제공한다. 과거 모든 실행을 탐색하는 화면, 검수 이벤트의 실행별 귀속 엔진, JSON/CSV 내보내기는 이번 필수 범위에 넣지 않는다.
- 변경 예정: `tools/run_batch.py`, 조회용 요약 로직과 필요한 API, `app/main.py` 또는 `app/review_api.py`, 웹 UI 파일, `test_batch.py` 및 요약/API·Node 검사. 새 모듈은 필요한 최소 크기로 분리한다.

### S3. 검수 현황 요약

- 집계 범위는 현재 검수 목록의 전체 현재 상태로 통일하고 화면에 범위를 표시한다. 실행별 생산성 통계로 오해하게 표시하지 않는다.
- `accepted`와 `accepted_edited`는 채택에 합산하고 필요하면 수정 후 채택을 보조 표시한다. `superseded`와 철회된 과거 이벤트는 현재 후보·최종 채택 수에 중복 합산하지 않는다.
- 자동·수동 출처 구분은 기존 저장 필드를 재사용한다. 수동 추가·저장·상태 변경·새로고침 후 요약을 갱신한다.
- 기존 유휴 제외 타이머와 검수 기록을 재사용한다. 저장된 검수 시간과 현재 작성 중 시간을 중복 합산하지 않고, 기록이 불완전하면 측정 범위를 함께 표시한다.
- 독립 검수 모드에서는 감정 정답 분포·모델 제안처럼 판단에 영향을 주는 정보를 추가로 노출하지 않는다.
- 변경 예정: `app/review.py` 또는 신규 조회용 요약 모듈, 필요한 조회 API, 웹 UI 파일과 관련 Python/Node 검사. 기존 저장 형식과 감정 모델은 유지한다.

### 이번 제외 범위

- 장면 전환 기반 자동 분할·자동 제외와 `strict` 모드.
- 3~12초 강제 정책, 짧은 발화 패딩, 후보 순위·선정 알고리즘 변경.
- 탈락 후보 전체 진단, 전체 실행 기록 엔진, CSV/JSON 보고서·과거 실행 비교 화면.
- 새 파일 해시 체계·최종 저장 구조 변경·데이터 마이그레이션.
- 신규 감정 모델, 대규모 정확도·시간 절감률 실험.

RTF(처리 시간 ÷ 영상 길이)는 이번 배치에서 발화 분석을 수행한 영상으로 계산한다. 장면 분석만 보완한 실행에서는 장면 분석 시간을 따로 확인한다.

### 시연 기능 재현 명령

WSL2 Ubuntu에서 `feat/advance` 변경분이 반영된 저장소 루트에서 실행한다.

```bash
cd emolabel-youtube
uv pip install scenedetect
uv run python -m unittest discover -v
node --test test_review_ui.mjs test_boundary_playback.mjs
EMOLABEL_SCENE_MODE=warn uv run python -m tools.run_batch --video-workers 1
EMOLABEL_SCENE_MODE=warn uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 `http://127.0.0.1:8000`을 열고 장면 경고·컷 이동, 배치 시간·캐시 여부, 검수 요약 및 저장 흐름을 확인한다.

### 시연 전 검증과 완료 체크리스트

기존 전체 회귀 명령은 6절을 사용하고 새 기능의 관련 검사도 함께 실행한다. 실제 브라우저 확인은 Ubuntu 실행 환경에서 진행한다. 검증하지 못한 항목은 완료로 표시하지 않는다.

- [ ] 기존 수집·재생·수동 추가·전사·확정 저장·새로고침/재실행 보존 확인.
- [ ] S1: 전환 있음/없음, 미설치·실패·캐시·원본 변경, 수동 구간·경계 수정에서 경고 확인.
- [ ] S2: 첫 실행/캐시 실행의 이번 처리 시간과 과거 시간이 구분되고 미측정 값이 0초로 표시되지 않음.
- [ ] S3: 자동·수동·채택·보류·제외·미검수 수치와 검수 시간이 실제 기록에 일치함.
- [ ] Python 관련 회귀·Ubuntu HTTP 검사·Node UI 검사 통과. 실행하지 못한 검사는 이유와 명령 기록.
- [ ] 실제 영상 1개로 전체 흐름과 장면 경고·시간·현황 표시를 확인하고 시연 영상 녹화. 장면 전환이 있는 구간을 사전에 선정한다.

시연에서는 측정값과 기능을 설명한다. 수동 작업 기준선 없이 사람 시간 절감률이나 감정 정확도 향상을 주장하지 않는다. 기능 문제가 발견되면 해당 선택 기능을 끄고 기존 검수·저장 흐름으로 시연할 수 있어야 한다.

## 1. 시연 이후 전체 개선안: 요구사항과 도입 범위

팀원의 [EmoLabel 2.0](https://github.com/mangopeach5/emolabel2)에서 확인한 장면 전환 검사, 선정 근거 기록, 실행별 통계, 해시 기반 검증을 현재 웹 검수 흐름에 맞게 도입한다. 코드와 정책은 우리 저장 구조에 맞춰 작성한다. 팀원 코드의 직접 복사·의존성 추가 전에는 라이선스 조건을 확인한다.

현재의 YouTube 수집, 파형 검수, 수동 구간 추가, 대사·음성 모델 50:50 평균 결합, 사람의 최종 확정은 유지한다. 자동 채택은 허용하지 않는다. 전체 복잡도는 **높음**이며 아래 단위로 나누어 구현·검증한다.

| 팀원 프로그램에서 확인한 장점 | 현재 EmoLabel의 구현 | 이번 계획 |
| --- | --- | --- |
| PySceneDetect 장면 전환 검사 | ASR·VAD 경계 보정과 품질 플래그, 장면 검사는 없음 | 선택형 장면 분석과 검수 경고 도입 |
| 후보별 선정·거절·보류 사유 | 최종 후보에 발화 비율·경계 사유 저장, 탈락 후보 전체 진단은 없음 | 탈락을 포함한 선정 진단 기록과 한국어 설명 |
| 3~12초 정책과 짧은 발화 패딩 | 3~12초 우선 순위, 설정상 허용 길이는 기본 0.2~60초 | 자동 후보용 선택형 길이 정책, 제한적 패딩 실험 |
| 실행별 처리 시간·RTF·검수 측정 구분 | 배치 단계 시간·모델 실행 기록·유휴 제외 검수 타이머 존재 | 실행 기록 연결과 JSON/CSV 보고서 추가 |
| 파일 해시·내보내기 검증 | 모델 평가 manifest에 SHA-256 존재, 후보 캐시는 크기·mtime 중심 | 최종 출력용 해시 기록과 읽기 전용 무결성 검사 |
| 승인 이력·배치 재개·성능 평가 | 검수 이력·원자적 저장·철회·재개·Macro-F1 계산 이미 존재 | 기존 구현 재사용, 별도 저장 엔진 재작성 없음 |

### 이번 범위에서 제외

- SQLite 중심 저장 구조로 전환하거나 기존 JSON 장부를 일괄 마이그레이션하는 작업.
- Qwen/Ollama로 기존 감정 모델 교체, 추가 감정 모델 비교 실험.
- 로컬 영상 등록·업로드, 채널 단위 수집 등 새로운 입력 방식.
- LLM 기반 경계 재작성, 서로 다른 ASR 발화 자동 병합, 의미상 문장 완결성 보장.
- 대규모 통계 대시보드 프레임워크 도입. 기존 검수 화면에 필요한 요약부터 표시한다.

## 2. 근거와 기존 구현 재사용

팀원 저장소의 `main` 코드를 2026-11-23에 확인했다. 구현 시에는 당시 커밋 SHA를 별도로 기록해 참고 버전을 고정한다. 팀원 프로그램을 이번 세션에서 직접 실행하지 않았으며 정확도·생산성 우위를 전제하지 않는다. 초기 설계 문서보다 실제 코드를 우선한다.

| 용도 | 현재 코드에서 따를 패턴 |
| --- | --- |
| 선정 함수·버전 | `app/candidates.py`: `select()`, `SELECTION_VERSION`, `quality_flags`, 원본 ASR 경계 보존 |
| 실패 처리 | `tools/run_batch.py`: 영상별 실패 기록 후 나머지 영상 계속 처리. `app/review_api.py`: 충돌 409, 입력 오류 422, 선택형 전사 실패 503 |
| 기록 형식 | `tools/run_batch.py`: 단계별 `seconds`와 JSON 출력. 캐시 산출물의 과거 시간을 현재 실행 시간으로 취급하지 않음 |
| 저장·잠금 | `tools/run_batch.py`: 영상별 SQLite 잠금, 임시 JSON 교체, `selection-history/` 보존. `app/candidate_media.py`: 완료 마커와 미디어 묶음 저장 |
| 검수·확정본 | `app/review.py`, `app/store.py`: 수동 후보·검수 이력·철회·확정본 보호 재사용 |
| 해시·평가 | `tools/emotion_batch.py`: 미디어 SHA-256. `tools/evaluate_models.py`: 고정 입력 지문·독립 정답·실패/누락 분모 유지 |
| 테스트 | `test_batch.py`: `unittest`, 임시 디렉터리, `unittest.mock.patch`로 모델·미디어 격리. UI는 기존 Node 테스트 방식 유지 |

이하 경로는 별도 표기가 없으면 `emolabel-youtube/` 기준이다. 신규 파일명은 계획이며 구현 시작 시 기존 모듈과 다시 대조한다.

## 3. 구현 순서와 의존성

시연 이후 전체 확장을 진행할 때의 순서는 **A 기존 기준선 확인 → B 실행 기록·선정 진단 → C 장면 검사·길이 정책 → D 무결성 검증 → E 화면 요약·실측 비교**다. 시연용 S1~S3에서 구현한 부분은 재사용하고 남은 확장만 진행한다. B의 기록을 사용해 C의 효과를 비교한다. 각 단계는 독립적으로 검토하고 기존 검수를 계속 사용할 수 있어야 한다.

### A. 기존 3.5단계 기준선 고정 — 복잡도 낮음

1. Ubuntu 작업 폴더의 미커밋 변경을 먼저 확인·보존하고 현재 브랜치를 안전하게 동기화한다. 강제 초기화로 맞추지 않는다.
2. 기존 전체 검사와 실제 수동 추가 → 전사 → 재생 → 채택 → 새로고침/재실행 보존을 확인한다. 실패는 새 기능 도입 전 기존 문제로 구분한다.
3. 개선 전 후보 목록·선정 버전·설정·입력 해시를 고정한다. 기존 정상 사례와 뒤 잘림 사례, 장면 전환·짧은 발화 사례를 포함한다.

- 변경 예정: 새 기준선 manifest·측정 기록은 Git 제외 `data/` 아래. 코드 변경 없음.
- 완료 기준: 기존 회귀 통과, 확정본 보존 확인, 비교 입력 목록과 환경 기록 확보.
- 현재 기록의 Python 142개·Node 13개 통과는 과거 결과이며 이 단계의 실행 결과를 대신하지 않는다. HTTP 포함 Python 148개는 기존 예상 수이며 실제 수집 결과를 기록한다.

### B. 실행 기록과 선정 진단 — 복잡도 중간

1. 배치 실행마다 `run_id`를 생성한다. 실행 설정·선정 버전·입력 지문·영상 ID·시작/종료·상태·단계별 현재 실행 시간과 캐시 여부를 기록한다.
2. `seconds`에 남은 기존 산출물 생성 시간과 이번 실행 소요 시간을 분리한다. 병렬 작업의 단계 시간 합계와 전체 wall time을 구분하고, 잠금 대기 시간도 분리한다.
3. `select()` 반환 형식은 유지하며 진단 수집 경로를 추가한다. 각 입력 ASR 구간의 제외/선정/순위 밀림 사유, 보정 전후 경계, 발화 비율·여백·경고를 기록한다.
4. `data/runs/{run_id}/`에 실행 메타데이터와 영상별 기록을 저장한다. 고유 경로·기존 파일 보존·임시 파일 교체를 사용하고 중단된 실행은 미완료로 구분한다.
5. 기존 검수 이벤트와 모델 run을 명시적 참조로 연결한다. 실행 당시 후보·결과 스냅샷과 현재 검수 상태를 분리하고, 과거 검수를 새 실행 실적으로 소급 계산하지 않는다.
6. 읽기 전용 `tools/workflow_report.py`로 JSON/CSV를 생성한다. 미측정 시간은 `null`, CSV에서는 빈칸과 측정 상태 필드로 표시한다. 0초로 채우지 않는다.

- 변경 예정: `tools/run_batch.py`, `app/candidates.py`, `app/review.py`, `tools/emotion_batch.py`; 신규 `app/run_records.py`, `tools/workflow_report.py`, `test_run_records.py`, `test_workflow_report.py`; 기존 `test_batch.py`, `test_candidates.py` 확장.
- 완료 기준: 첫 실행/캐시 실행/부분 실패/중단 기록이 구분되고 재실행으로 과거 보고서가 바뀌지 않는다. 같은 후보의 경계 수정·수동 추가·철회가 중복 집계되지 않는다. 기존 선정 결과는 B 도입 전과 같다.
- 검증: 실제 모델 없이 임시 파일·모의 시계로 시간 귀속, 잘못된 지문, 중복·손상 기록, 병렬 기록 충돌을 검사한다.

### C. 장면 전환 경고와 자동 후보 길이 정책 — 복잡도 높음

1. 신규 `app/scene.py`에 장면 감지 어댑터를 분리한다. PySceneDetect는 선택 의존성으로 설치하고 늦게 import한다. 기본값 `off`, 첫 실험 `warn`, 선택형 `strict`를 제공한다.
2. `scene.json` 캐시에 원본 지문·분석기 버전·감지 설정·컷 시각을 저장한다. 감지 설정·길이 정책·분석 결과 지문을 선정 캐시 키에 반영하고 변경 전 후보 목록을 보존한다. 기존 선정 버전만 비교하는 무효화 경로도 함께 보완한다.
3. `warn`에서는 장면 전환이 있는 후보를 보존하고 경고·재생 위치를 제공한다. 컷이 화자 전환이라는 단정은 하지 않는다. 경고만으로 채택을 금지하지 않는다.
4. `strict`에서는 발화 중 컷은 자동 선정에서 제외하고 진단에 남긴다. 무음 중 컷은 독립적으로 유효한 발화 구간이 남는 경우에만 분할한다. 새 경계·길이·대사 대응을 다시 검증하고, 불명확하면 자동 분할하지 않는다.
5. 자동 후보 길이 정책을 `legacy` / `prefer_3_12` / `strict_3_12`로 분리한다. 기본은 현재 동작인 `legacy`; 전역 `MIN_CLIP_S`·`MAX_CLIP_S`를 일괄 변경해 수동 추가나 기존 확정본에 적용하지 않는다.
6. 짧은 발화 패딩은 별도 opt-in 실험으로 둔다. 초기 제안값은 각 방향 최대 0.5초, 총 확장 최대 1초다. 원본 끝·주변 ASR/VAD 발화·장면 경계를 넘지 않고 3초를 확보할 수 있을 때만 확장한다. 조건을 만족하지 못하면 억지로 채우지 않는다.
7. 장면 분석이 미설치·실패하면 `warn`에서는 분석 불가 표시와 기존 선정으로 계속한다. `strict` 요청에서는 해당 영상의 장면 단계 실패를 명시하고 성공으로 처리하지 않는다. 기존 수동 검수는 계속 허용한다.

- 변경 예정: 신규 `app/scene.py`, `test_scene.py`; `app/candidates.py`, `app/config.py`, `tools/run_batch.py`, `pyproject.toml`, 관련 잠금 파일, `.env.example`, `test_candidates.py`, `test_batch.py`.
- UI 예정: `static/review.mjs`, `static/app.js`, `static/index.html`, `static/style.css`, `test_review_ui.mjs`에 한국어 경고·분석 불가·근거 표시.
- 완료 기준: `off + legacy`에서 기존 결과 유지. 발화 중 컷·무음 중 컷·원본 끝·인접 발화·미설치·캐시 설정 변경을 검사한다. 감지 정책 전환이 수동 후보와 사람 라벨을 변경하지 않는다.
- 실환경 검증: Ubuntu CPU에서 컷/페이드/빠른 편집/전환 없는 영상을 확인한다. 하드 컷부터 도입하고 페이드 감지는 실측 후 켠다. 후보 감소만으로 경계 개선이라고 기록하지 않는다.

### D. 확정 출력 무결성 검사 — 복잡도 중간

1. 원본·후보·최종 MP4/WAV의 SHA-256을 용도별로 기록한다. 모델 manifest의 해시 구현을 재사용할 공통 함수로 정리한다.
2. 새 확정 저장 시 최종 미디어를 검증한 후 무결성 메타데이터를 기록한다. `annotation.json`이 최종 완료 마커인 기존 순서를 유지한다. 감정·대사·경계 변경과 철회 시 메타데이터도 일치시킨다.
3. 기존 확정본은 자동 수정하지 않는다. 해시 없는 과거 데이터는 `unverified_legacy`, 파일 불일치는 `mismatch`, 파일 누락은 `missing`으로 구분한다.
4. `tools/dataset_status.py`에 선택형 상세 검사를 추가한다. 손상 발견 시 경고와 실패 종료 코드를 반환하되 파일 삭제·자동 복구는 하지 않는다.
5. SHA 계산은 저장·명시적 검사에서 수행하고 UI 목록 조회마다 대용량 파일을 읽지 않는다. 동일 해시 입력은 우선 중복 경고로 다루고 기존 video ID·출처를 자동 병합하지 않는다.

- 변경 예정: 신규 `app/integrity.py`, `test_integrity.py`; `app/review.py`, `app/store.py`, `tools/emotion_batch.py`, `tools/dataset_status.py`, `test_review.py`, `test_manual_candidates.py`, `test_dataset_status.py`.
- 완료 기준: 동일 크기로 내용이 바뀐 파일, 부분 복사, 원본 변경, 저장 중 실패, 과거 형식, 채택 철회가 올바르게 구분된다. 확인 실패로 기존 확정본·라벨을 잃지 않는다.

### E. 웹 요약과 동일 조건 파일럿 — 복잡도 중간

1. 기존 검수 화면에 실행 선택과 작은 통계 영역을 추가한다. 영상 성공/실패/후보 없음, 자동·수동 후보 수, 채택·보류·제외, 경계 수정, 실측 사람 시간, 처리 시간·RTF를 표시한다.
2. 읽기 전용 `app/analytics.py`와 `app/analytics_api.py`를 추가해 B의 보고 로직을 공유한다. 기존 `app/main.py`에 연결하고 검수 저장 API는 재사용한다. 화면에서 자동 재추론·재선정을 실행하지 않는다.
3. 실행 당시 결과/현재 상태, 첫 실행/캐시, 자동 후보/수동 추가를 구분한다. 독립 검수 중에는 모델 예측이나 정답 분포 등 판단에 영향을 줄 정보를 숨긴다.
4. 개선 전 v3, `warn`, 선택형 `strict`를 같은 원본으로 비교한다. 최소 10개 원본의 개발 파일럿을 제안하되 정상/잘림/빠른 컷/짧은 발화/BGM 사례를 포함한다. 정책 조정 자료를 최종 평가 자료와 분리한다.
5. 사람 시간 비교는 모델 제안을 가린 조건과 동일 검수 기준으로 진행하고 순서를 번갈아 배정한다. 이미 본 영상의 학습 효과를 기록한다. 팀원 프로그램과의 최종 비교는 기존 PLAN 4단계의 독립 정답·분리 조건을 따른다.

- 변경 예정: 신규 `app/analytics.py`, `app/analytics_api.py`, `test_analytics.py`, `test_analytics_api.py`; `app/main.py`, 웹 UI 파일·Node 검사, `emolabel-youtube/README.md`.
- 완료 기준: UI 수치와 JSON/CSV 보고서가 일치한다. 측정하지 않은 수치는 미측정으로 표시하고 0건 분모는 계산하지 않는다. 모델 품질 계산은 기존 `tools/evaluate_models.py`를 재사용한다.

## 4. 비교 지표와 채택 판단

| 지표 | 정의·판정 |
| --- | --- |
| 채택 클립당 사람 시간 | 해당 실험에 귀속된 활성 작업 시간 ÷ 미디어·annotation이 유효한 최종 채택 수. 수동 추가 시간 포함, 중복 시간 합산 금지. 채택 0건 또는 측정 불완전이면 산출 불가 |
| 후보 경계 품질 | 잘림 건수/검수 건수, 경계 수정 건수/검수 건수, 제외 사유. 정상 발화를 잃은 사례도 기록 |
| 산출량 | 원본당 최종 유효 클립 수, 수동 복구 건수. 후보를 줄여 얻은 겉보기 개선과 구분 |
| 처리 시간·RTF | 현재 실행 처리 초 ÷ 실제 처리 원본 초. 첫 실행·캐시 분리, 병렬 전체 wall time과 영상별 시간 분리 |
| 감정 품질 | 기존 독립 정답 평가 도구의 전체 분모/유효 예측 분모, Macro-F1·재현율·미제안율 사용. 신규 정책별 후보가 다르면 동일 후보 모델 품질과 전체 워크플로우 품질을 분리 |
| 무결성 | verified / unverified_legacy / mismatch / missing 수. 미검증을 정상이나 손상으로 단정하지 않음 |

개발 파일럿에서 사람 시간 감소와 산출량·품질 손실을 함께 검토한 뒤 기본 정책을 결정한다. 장면 `strict`와 `strict_3_12`는 결과 확인 전 기본값으로 승격하지 않는다. 최종 비교의 허용 손실 기준은 결과를 보기 전에 팀과 정한다. 기존 PLAN의 모델 품질 기준을 이 문서에서 완화하지 않는다.

## 6. 검증과 최종 완료 체크리스트

자동 검사는 실제 모델·네트워크 다운로드 없이 기존 테스트 패턴으로 구성하고, 장면 감지 실물·브라우저·CPU 시간은 Ubuntu 파일럿으로 별도 확인한다. 이번 세션은 문서만 작성했으므로 아래 검사를 실행한 것으로 기록하지 않는다.

```bash
# WSL2 Ubuntu, emolabel-youtube/에서 실행
uv run python -m unittest -v test_portability
uv run python -m unittest discover -v
node --test test_review_ui.mjs test_boundary_playback.mjs
```

각 단계의 신규 테스트는 전체 discover에 포함한다. HTTP 검사는 Ubuntu에서 실행한다. 실행할 수 없으면 환경·오류·재현 명령을 인계에 남긴다. 문서·코드는 UTF-8/LF와 `git diff --check`로 확인한다.

- [ ] A: 기존 회귀·수동 추가·사람 확정본 보존 및 기준선 확보.
- [ ] B: 실행별 기록·선정 진단·JSON/CSV 보고서 검증.
- [ ] C: 장면 off/warn/strict·길이 정책·패딩·캐시·수동 후보 보존 검증.
- [ ] D: 신규 해시·과거 형식·손상·철회·저장 실패 검증.
- [ ] E: 화면/보고서 수치 일치·독립 검수 보호·개발 파일럿 비교.
- [ ] 실측 결과와 기본 정책 결정 근거 기록. 기존 4단계 비교의 독립 평가 자료 보존.
